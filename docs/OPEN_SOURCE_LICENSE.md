## 2. 为什么是 Apache-2.0

三个原因：

1. **生态兼容**：我们的技术底座 PX4（BSD-3）、ROS 2（Apache-2.0）、Gazebo（Apache-2.0）都是宽松协议，Apache-2.0 与之完全兼容，不和任何依赖冲突；
2. **科研友好**：高校和科研院所可以放心使用、修改、发论文，甚至可以用于商业项目——这符合产品"开源引流、服务变现"的定位；
3. **自带防御机制**：Apache-2.0 不只是"随便用"，它包含明确的**专利授权与专利反制条款**和**商标保护条款**（见第 4、5 节），这是 MIT/BSD 等更短协议没有的。

## 4. 商标保护（防山寨的核心）

Apache-2.0 第 6 条明确规定：协议**不授予任何商标使用权**。

- "灵簇"、"SwarmCore" 及配套标识是我司商标（申请注册中）；
- 任何人可以 fork、修改、再分发代码，但**不得以 "SwarmCore"/"灵簇" 名义发布衍生作品**，不得使用容易混淆的近似名称与标识；
- 这意味着：即使有人原样复制我们的仓库，他也只能以别的名字分发——**品牌、渠道、案例积累无法被代码复制带走**。

如果你看到第三方以 "SwarmCore"/"灵簇" 名义提供产品或服务，那不是我司行为，请联系我们（见第 8 节）。

## 5. 专利保护机制

Apache-2.0 第 3 条包含两层专利安排：

1. **专利授权**：我们（及每位贡献者）授予你使用本软件所需的专利许可，永久、免费、全球范围；
2. **专利反制（retaliation）**：如果你就本软件对我们或任何用户提起专利诉讼，你获得的专利许可**自动终止**。

这一条款是大型企业敢用 Apache-2.0 项目的原因，也是对"抄袭后反告我们"这类恶意行为的制度性防御。

## 6. 多层原创保护体系

开源不等于放弃权利。我们的原创保护由五层构成：

| 层 | 机制 | 保护什么 |
| --- | --- | --- |
| 著作权 | 代码完成即自动产生，协议要求保留署名 | 代码不被"抹去作者" |
| 商标 | "灵簇"/"SwarmCore" 注册（进行中） | 品牌与商誉不被冒用 |
| 专利条款 | Apache-2.0 授权+反制 | 不被专利讹诈 |
| 商业双轨 | 真机参数、标定工具、评估脚本为商业交付物，不开源 | 核心工程数据不外流 |
| 证据链 | 完整 git 提交历史 + Gitee/Gitea 双远端时间戳 | 原创时间与作者可举证 |

## 7. 第三方组件合规

我们对依赖组件的合规义务已经全部落实，你继续使用/分发时也请维持：

- **PX4-Autopilot（BSD 3-Clause）**：其版权声明已随源码保留在 `PX4-Autopilot/` 目录内；以"拍平快照"分发不违反 BSD 条款（BSD 允许源码/二进制再分发，只要求保留声明）。注意其内置的 pymavlink 生成器为 LGPL——我们仅在**编译期**使用它生成代码，不修改、不静态链接其运行库，属于 LGPL 明确允许的使用方式；
- **Micro-XRCE-DDS-Agent（Apache-2.0）**：协议兼容，声明见 `NOTICE`；
- **px4_msgs / px4_ros_com（BSD 3-Clause）**：保留 PX4 原始版权头，其 `package.xml` 中的 BSD 许可声明未做改动；
- **ROS 2 / Gazebo**：系统级运行时依赖，不随仓库分发，无额外义务。
