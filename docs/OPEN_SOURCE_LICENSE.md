## 2. 为什么从 Apache-2.0 换成 GPL/LGPL 分层

Apache-2.0 是宽松协议：任何人可以把我们的代码改一改、做成闭源产品，反过来与我们竞争，且没有任何义务回馈社区。对公司"全开源引流、服务变现"的商业模式而言，这等于邀请竞品白嫖。

换成 copyleft 分层后的效果：

1. **GPL v3 保护核心**：竞品若基于 bringup / ground_station / swarm_msgs 做衍生产品并对外分发，就必须开源其全部改进——要么为社区（也即为我们）打工，要么不用。GPL v3 还自带明确的专利授权条款与反 Tivoization 条款，在国内维权时比宽松协议有实际的法律抓手；
2. **LGPL v3 留住用户**：swarm_api 是高校师生 import 来写自己科研代码的框架。若它也 GPL，用户的上层代码可能被传染，会直接劝退核心用户群。LGPL 保证"用我们的库不必开源你的代码，改我们的库才需开源"——保护与用户友好兼得；
3. **与底座零冲突**：PX4（BSD-3）、ROS 2（Apache-2.0）、Gazebo（Apache-2.0）均为宽松协议，允许与 GPL/LGPL 代码共同分发与链接，copyleft 义务只及于自研代码自身的衍生作品，不及于第三方组件；
4. **保留商业出口**：配合贡献者协议（见第 8 节），我们保留**双许可**权利——企业若想闭源商用 GPL 部分，可向我们购买商业许可证（Qt、MySQL 的经典变现路径）。

- "灵簇"、"SwarmCore" 及配套标识是我司商标（申请注册中）；

GPL v3 与 LGPL v3 均包含明确的专利安排：

1. **专利授权**：我们（及每位贡献者）授予你使用本软件所需的专利许可，永久、免费、全球范围；
2. **专利反制（retaliation）**：如果你就本软件对我们或任何用户提起专利诉讼，你依据协议获得的全部权利**自动终止**。

这是 GPL v3 相对 MIT/BSD 的实质优势之一，也是对"抄袭后反告我们"这类恶意行为的制度性防御。此外，公司针对架构级创新点（集群通信协议、端-边-云计算拆分、异构蜂群角色调度等）另有防御性专利布局，与本协议互为补充。

## 6. 多层原创保护体系

开源不等于放弃权利。我们的原创保护由五层构成：

| 层 | 机制 | 保护什么 |
| --- | --- | --- |
| 著作权 + Copyleft | 代码完成即自动产生著作权；GPL/LGPL 要求衍生作品开源 | 核心代码不被闭源白嫖 |
| 商标 | "灵簇"/"SwarmCore" 注册（进行中） | 品牌与商誉不被冒用 |
| 专利条款 + 防御性专利 | GPL v3 授权+反制；架构级发明专利申请 | 不被专利讹诈、不被抢注反诉 |
| 商业双轨 | 真机参数、标定工具、课程、评估脚本为商业交付物，不开源 | 核心工程数据与服务收入不外流 |
| 证据链 | 完整 git 提交历史 + Gitee/Gitea 双远端时间戳 | 原创时间与作者可举证 |

自研代码（GPL v3 / LGPL v3）与上述宽松协议组件共同分发与链接**不存在许可证冲突**：宽松协议允许这样做，copyleft 义务只及于自研代码自身的衍生作品，不及于第三方组件。
